是否需要 30 分鐘穩定測試？

需要，但不是現在直接把本次任一級別延長到 30 分鐘。階梯測試用來找候選容量；耐久測試用來驗證候選容量在時間拉長後不會累積 queue、記憶體、KV cache、儲存或連線問題。

  1. 先修正／釐清兩類 60 秒錯誤，並讓壓測將 [ERROR] 或缺少 [END] 判定為失敗。
  2. 開啟 REQUIRE_DONE_MARKER=1，同步收集 vLLM /metrics 與 H200 GPU 指標。
  3. 重新跑 5 分鐘階梯測試；選擇最高且同時符合：完成率 ≥99%、p95 TTFT ≤3 秒、p95 E2E ≤10 秒、waiting queue 不持續上升的級別。
  4. 用該候選級別跑至少 30 分鐘；正式上線容量建議保留 20–30% headroom。若是正式驗收，建議延長到 60 分鐘。
本次從 1 user 就只有 66.7% 完整完成率，因此目前沒有合格的 30 分鐘候選級別。先修可靠度，再做 soak test，否則只是把同一錯誤重複更久。

限制與下一步

  • 測試只使用 short profile 的單一題型，尚未涵蓋 mixed prompt。
  • 每筆都新建 conversation；這會同時壓到應用服務與儲存層，不是純 vLLM benchmark。
  • 建議下一輪採每個虛擬 user 重用 conversation、每筆使用唯一 chat ID，以減少非模型路徑干擾。
  • 需要查服務端日誌確認「紀錄儲存失敗」與「模型通訊異常」的根因。
